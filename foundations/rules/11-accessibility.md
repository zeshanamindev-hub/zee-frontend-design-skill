# 11 · Accessibility rules (A1–A9)
Testing: `scripts/interaction-qa.mjs` (keyboard, focus, dialogs, sliders, names, video) + `scripts/contrast.py` + a manual screen-reader pass.
Law (verified Nov 2026): the EU Accessibility Act has been enforceable since 28 June 2025. **EN 301 549 V4.1.1** (published 2 Sept 2026 by ETSI/CEN/CENELEC) references **WCAG 2.2 AA**, while V3.2.1 (WCAG 2.1 AA) is still the version cited in the EU Official Journal. **Target WCAG 2.2 AA.** [Source: deque.com/en-301-549-compliance; dwt.com 2026-09 EAA update]

| ID | Rule | How to apply | Honest caveat |
|---|---|---|---|
| **A1** | **POUR** (Perceivable, Operable, Understandable, Robust) | Use as the frame of every audit: can everyone perceive it (alt, captions, contrast), operate it (keyboard, targets, time), understand it (labels, errors, consistent nav), and is it robust (valid semantics, ARIA only when needed)? | POUR is the structure of WCAG, not a separate checklist. |
| **A2** | **WCAG 2.2 guidelines** | Level AA conformance = 55 success criteria (31 at A + 24 at AA; 86 in total incl. AAA). New in 2.2 at A/AA (6): 2.4.11 Focus Not Obscured (min), 2.5.7 Dragging Movements, 2.5.8 Target Size (min 24px), 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication (min); +3 at AAA (2.4.12, 2.4.13 Focus Appearance, 3.3.9). 4.1.1 Parsing removed. | Automated tools catch only a share of issues (often cited ~30–40%); manual testing is required. |
| **A3** | **Colour contrast** | Text 4.5:1, large text 3:1, UI components & graphics 3:1 (1.4.11), focus indicators 3:1. Test hover/disabled/placeholder too. Text over images: overlay/scrim (Kennedy methods in `../../mediums/web-ui/craft-details.md`). | Disabled controls are exempt, but they still need to be perceivable as disabled. |
| **A4** | **Keyboard accessibility** | Everything operable by keyboard; logical tab order (DOM order); no traps; custom widgets follow WAI-ARIA APG patterns (tabs: arrows; menus: arrows + Escape; dialogs: focus in, Escape closes, focus returns); skip link first. Carousels: pause control + keyboard. | Keyboard-only users and screen-reader users have different needs; test both. |
| **A5** | **Focus visibility** | `:focus-visible` ring ≥ 2px, ≥ 3:1 against both the component and the background (two-tone ring: 2px ink + 2px offset in bg colour works on any surface); not hidden by sticky headers (2.4.11, use `scroll-padding-top`). | Never `outline: none` without a replacement. |
| **A6** | **Semantic HTML** | Landmarks (`header`, `nav`, `main`, `footer`), one `h1`, ordered headings, `button` for actions / `a` for navigation, `label` for inputs, lists for lists, `table` for tabular data. ARIA only to fill gaps ("no ARIA is better than bad ARIA"). | Also helps SEO and AI agents read the page (MX design). |
| **A7** | **Accessible typography** | Body ≥ 16px, line-height supports 1.5 user override (1.4.12), no text in images, resizable to 200% without loss (1.4.4), reflow at 320px width (1.4.10), avoid all-caps paragraphs and light weights < 300 for text. | Dyslexia "special fonts" show little evidence of benefit; good spacing helps more. |
| **A8** | **Target size** | WCAG 2.2 AA: ≥ 24×24 CSS px or enough spacing; recommended 44×44 (iOS) / 48×48 dp (Android). | Inline text links are exempt from 2.5.8. |
| **A9** | **Screen-reader compatibility** | Meaningful alt (empty `alt=""` for decorative images), accessible names for icon buttons, `aria-live` for async results/toasts, form errors linked with `aria-describedby`, captions + transcripts for video, `prefers-reduced-motion` respected. Test with VoiceOver (macOS/iOS) and NVDA (Windows). | Over-labelling (ARIA on everything) makes pages noisy for screen-reader users. |
