# 06 · Dashboard design rules (D1–D14)
Full dashboard medium (layouts, components, chart choice, states): `../../mediums/dashboard/dashboard.md`. Chart colours: the `dataviz` approach of categorical / sequential / diverging palettes in `../color-system.md` §6.

| ID | Rule | How to apply (numbers) | Honest caveat |
|---|---|---|---|
| **D1** | **Information hierarchy** | Three tiers: **KPI strip** (3–6 numbers, top) → **trend & breakdown charts** (middle) → **detail tables/lists** (bottom or drill-down). The top-left slot holds the most important metric. | Role-based dashboards may need different tier-1 metrics per role. |
| **D2** | **Data-ink ratio** (Tufte) | Remove chart junk: no 3D, no heavy gridlines (use 1px at 10–15% contrast or none), no backgrounds/borders on charts, direct labels instead of legends where possible. | Pushed too far, charts lose orientation cues; keep the axes needed to read values. |
| **D3** | **Data density** | Operational dashboards: dense (4-pt spacing, 13–14px table text, 32–40px rows). Executive dashboards: sparse (fewer, larger numbers). Offer a density toggle for tables. | Density ≠ clutter; alignment and consistent number formats make density readable. |
| **D4** | **Overview first, zoom and filter, then details on demand** (Shneiderman's mantra) | Summary → filter bar (date range, segment) → click a chart to drill into a filtered table → row opens a side panel (not a new page). | Drill paths must preserve context (breadcrumb of filters). |
| **D5** | **Progressive disclosure** | Hide secondary metrics behind tabs or "show more"; tooltips for definitions; advanced filters collapsed. | Don't hide the metric a role checks daily. |
| **D6** | **Dashboard scanning pattern** | Users scan top-left → right → down (Z on sparse, F on dense). Align cards to one grid; same-height rows; KPI labels above numbers. | Strong colour (alerts) overrides the pattern. Use it only for real alerts. |
| **D7** | **KPI prioritisation** | Each KPI tile = **label · value · delta vs period (▲/▼ + %) · sparkline · target/benchmark**. ≤ 6 KPIs above the fold. Define the time window in the tile. | A number without comparison is meaningless; a delta without a period is misleading. |
| **D8** | **Signal-to-noise ratio** | Colour only what needs attention (exceptions, thresholds); everything else neutral grey. Alert colour ≤ 5% of the screen. | Users can't see a "normal" state if there's no baseline; show targets. |
| **D9** | **Small multiples** (Tufte) | Many small charts with the **same axes and scale**, one per segment/region, in a grid, instead of one spaghetti chart with 8 lines. | Shared scales must be truly shared; independent scales mislead. |
| **D10** | **Gestalt grouping** | Group related metrics in a common region (U23) or with whitespace; put filters next to what they filter. | Too many panels = box layout; use spacing and headers before borders. |
| **D11** | **Contextual data visualisation** | Choose the chart from the question: trend → line; comparison → bar (horizontal for long labels); part-to-whole → stacked bar (pie only for ≤ 3 parts); distribution → histogram/box; relationship → scatter; geo → map; single value vs goal → bullet chart. Always add context (target, previous period, benchmark). | Donut and gauge charts are popular but read poorly; prefer bars and bullet charts. |
| **D12** | **Colour-coded status** | Fixed semantic set: success, warning, danger, info, neutral. Always pair with icon + text (C12). Don't use red/green for non-status data series. | Red/green is the most common CVD confusion; use blue/orange for diverging data. |
| **D13** | **Consistent chart encoding** | Same metric = same colour, same unit format, same axis direction on every chart and page; a legend order that matches the visual order; time always left→right. | Re-colouring a series between charts silently breaks comparisons. |
| **D14** | **Data-driven design** | Design with **real or realistic data** (edge cases: 0, null, 1,000,000, very long names, negative deltas, loading, error, empty). Never lorem-ipsum numbers. | Fake "perfect" data hides layout breaks; test the worst case. |
