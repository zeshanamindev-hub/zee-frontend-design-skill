# 02 · Layout & composition rules (L1–L20)
Section layout catalogue: `../../mediums/web-ui/layout-library.md`. Physics of weight and optics: `../design-laws-and-physics.md`.

| ID | Rule | How to apply (numbers) | When | Honest caveat |
|---|---|---|---|---|
| **L1** | **Rule of thirds** | Place the focal point (face, product, headline start) on a third-line intersection; e.g. hero copy in columns 1–7 of 12, image focal point near x ≈ 66%. Set `object-position` so crops keep the subject on a third at every breakpoint. | Heroes, photography, posters | A compositional habit, not a usability law. Centred symmetry is often stronger for a single object. |
| **L2** | **Golden ratio (φ ≈ 1.618)** | Split layouts 61.8 / 38.2 (e.g. `grid-template-columns: 1.618fr 1fr`); type scale ratio 1.618 for posters only. | Asymmetric hero splits, editorial | **[Evidence: weak]** Claims that φ is inherently "most beautiful" are not supported. Treat it as one pleasant ratio among 3:2, 2:1 and 4:3. |
| **L3** | **Fibonacci sequence** | Spacing or size steps 8, 13, 21, 34, 55, 89 (× 1px) when you want organic progression. | Expressive spacing scales, illustrations | Overstated in design lore; an 8-pt scale (S1) is easier to maintain. |
| **L4** | **8-point grid** | See S1. All layout dimensions in multiples of 8 (8, 16, 24, 32, 48, 64, 96, 128). | Default for web & app | Off-grid optical tweaks are still allowed (icons, type baselines). |
| **L5** | **4-point grid** | See S2. Half-steps for dense UI: 4, 12, 20, 28. | Dashboards, mobile, small components | Mixing 4 and 8 without rules creates noise; define which components use 4. |
| **L6** | **Gestalt principles** | Proximity (U15), similarity (U16), common region (U23), uniform connectedness (U24), closure, continuity, figure-ground (B8), Prägnanz (U17). Group by **space first**, then by shared container, then by colour. | Every layout | Containers (cards) are the weakest grouping; overuse produces "box layout" (see L19). |
| **L7** | **Z-pattern** | For sparse pages: logo top-left → nav/CTA top-right → diagonal to content → primary CTA bottom-right of the block. | Landing pages, heroes with little text | Eye-tracking patterns describe *default* scanning; strong visual anchors override them. |
| **L8** | **F-pattern** | For text-heavy pages, put the key words at the **start** of headings and lines; use descriptive subheads every 3–5 paragraphs; front-load bullets. | Blogs, docs, search results, listings | NN/g describes F-pattern as a *failure mode* of unstructured text. Design to break it with clear hierarchy, not to exploit it. |
| **L9** | **Visual hierarchy** | Rank every element 1–3 before designing. Level 1 gets ≥ 2 of: size (≥ 2× body), weight, contrast, isolation (space), colour. Only **one** level-1 element per viewport. Squint test: blur to 5px, and the order must still read. | Always | Too many "level 1" items = no hierarchy. |
| **L10** | **Balance & symmetry** | Symmetric layouts (centred axis) for trust, ceremony and single-product focus. Keep both sides equal in *visual weight*, not just size. | Luxury, institutional, product launch | Symmetry everywhere is a top AI-slop tell (everything centred). Use it deliberately, ≤ 1–2 sections per page. |
| **L11** | **Asymmetrical balance** | Balance a heavy element (large image) with several lighter ones (text block + whitespace). Common splits: 7/5, 8/4, 5/7 of 12; offset images that break the container. | Editorial, modern brand sites | Needs a strong grid underneath or it reads as accidental. |
| **L12** | **Rule of odds** | Group 3 or 5 items (features, photos, stats) rather than 2 or 4 when composing visuals. | Feature trios, galleries, collages | Content beats composition: never invent a 3rd feature to reach "odd". 2 or 4 real items are fine. |
| **L13** | **Negative space** | Section padding ≥ 96px desktop / 64px mobile for marketing pages; content-to-container ratio ≤ 70% in hero; double what feels enough (Kennedy R3). | Premium, editorial, any page that feels cramped | Dashboards need density (D3); don't apply marketing whitespace to data tools. |
| **L14** | **Proximity principle** | Space inside a group < space between groups (ratio ≥ 1:2, e.g. 16px inside / 48px between). Separate destructive actions (delete, quit) from common ones. | Forms, cards, nav | [Source: figma.com/resource-library/ui-design-principles] |
| **L15** | **Alignment principle** | Every element aligns to a grid line or another element's edge. One strong left edge per section; avoid mixing centred and left text in one block. | Always | Optical alignment (icons, quotes, round shapes) may need 1–4px offsets. |
| **L16** | **Repetition principle** | Repeat a small set of devices (one card style, one button style, one divider, one accent shape) so the page reads as one system. | Systems, multi-page sites | Repetition ≠ every section identical (see L19, layout variety rules). |
| **L17** | **Unity principle** | All sections share type, colour, radius, spacing and motion language; vary *layout* and *scale* between sections, not the visual language. | Whole-page review | Unity with no contrast = monotony. Pair with L9 and the variety rules. |
| **L18** | **CRAP (Contrast, Repetition, Alignment, Proximity)** | Quick audit lens (Robin Williams): Is there enough contrast between levels? Are styles repeated? Is everything aligned? Are related things close? | Fast critique | A checklist, not a design method. |
| **L19** | **Card test** | Remove the border, shadow, background and radius from a card. If understanding doesn't suffer, it shouldn't be a card. No cards in the hero; no nested cards; ≤ 1 card grid per page. | Every section using boxes | Cards *are* right for discrete, comparable, clickable items (products, posts, plans). [Source: DAE-UX steering, card.md] |
| **L20** | **First-viewport tests** | *Brand test*: hide the nav. Could the viewport belong to a competitor? If yes, branding is too weak. *Image test*: remove the image. If the viewport still works, the image is decoration; replace it with one that carries the story. *Poster test*: the first viewport should read like a poster: one idea, one anchor, one action. | Every hero | [Source: DAE-UX steering, design-guidelines.md] |
